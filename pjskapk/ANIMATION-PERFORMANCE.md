# 持续动画卡顿诊断 · 2026-09-08

本次只诊断，未修改主题运行代码/粒子数量/视觉参数。前一轮NAV-SHELL验证的是导航Promise耗时与资源复用，不是稳定帧率；55–231ms不能证明动画流畅。

## 用户补充与归因限制

用户明确正常基准是“history.back改为固定上级之前”，普通Chrome全新刷新/静置也卡，而不是仅软导航多次后卡。此前“查清楚”措辞过度：粒子热点证据只说明当前稳态瓶颈，不能证明它解释了历史回归。

`tools/profile-router-ab.cjs`同设备/viewport/DPR进行了当前直接加载、当前软切换、在隔离请求响应中撤销router及恢复旧事件宿主的重建对照。3秒窗口分别227/204/209帧，ScriptDuration2.670/2.677/2.671秒，P95约20.6/20.8/20.8ms；移除router并未消除该CPU热点。此对照不是用户当时正常版本的完整快照，未恢复当时缓存/浏览器文档状态，不能据此否认用户回归观察。

固定上级那次已知编辑仅为layout/post返回href与删除history.back处理；它在没有点击时不执行粒子逻辑。此前历史文档是否携带更早的页面实现/状态仍未知；没有证据时不能把缓存作为已确认原因。当前尚未定位“历史正常→固定返回后静置卡”的完整因果链。诊断脚本没有更改站点运行代码，故本轮刷新仍会保持原性能。

## 测试方法

`tools/profile-animation.cjs`：独立Chrome headless，1920×1080 CSS px、DPR1.25，真实本机GPU环境；requestAnimationFrame包装测回调时间、2.5秒窗口帧间隔，CDP CPU Profiler与Performance metrics。各项单独在测试页暂停effects/characters/tree回调或去除CSSblur，结束关闭测试浏览器，不改变用户页或源码。不是用户当前标签页的逐帧录制，绝对值会受设备/窗口影响。

## 具体代码原因

`home-effects.js:153`按mesh每个三角面的索引逐项计算，而不是按唯一顶点复用。厚三角mesh有30个顶点、18个面（54次顶点处理）；每个顶点和法线分别执行两层rotate，rotate内部每次重复12个sin/cos调用，还在顶点循环中重复取尺寸曲线/构造数组。每组每帧还创建vertices数组、新Float32Array，再上传bufferData；动态角速度每粒子每轴进行32步曲线积分。原游戏网格/曲线是资源依据，但这些CPU循环不是恢复的Unity方法体，是网页移植实现，责任不在素材必须如此昂贵。

`tools/profile-particle-cost.cjs`在隔离浏览器通过请求响应插桩计数（不修改原文件），2秒窗口：

| 世界 | 预分配粒子 / 组 | 每帧rotate次数 | 粒子回调均值（含插桩开销） |
| --- | ---: | ---: | ---: |
| ？？？27 | 244 / 27 | 21601 | 17.14ms |
| 教室5 | 321 / 17 | 11833 | 9.84ms |
| 舞台7 | 329 / 20 | 27406 | 25.23ms |

预分配粒子数不等于当前可见数量。area27一帧约26万次三角函数调用，仅rotate就足以占用大部分帧预算；舞台更重。60Hz帧预算16.67ms、144Hz6.94ms，因此输入/UI/点击动画与粒子共用主线程时会一起卡，不只是页面切换。

## 为什么这次看起来“所有页面都卡”

所有内页此前已挂载完整选中世界；常驻导航复用了同一个昂贵渲染器，没有降低逐帧CPU成本。重复切换和新打开都能复现相近开销，不能说目前有证据证明router导致RAF泄漏。前轮只优化重载延迟且没有测持续帧率，漏掉了独立的稳态性能问题。

## 建议修复范围（尚未实施）

先按粒子每帧计算一次旋转矩阵/三角函数和尺寸系数，唯一顶点/法线变换后复用索引；缓存常量曲线、光方向、复用typed buffers，避免内层数组分配。必要时把变换迁到vertex shader。保持原碎片数量、透明度、模型、动作曲线和模糊外观，不用删素材/禁用动画掩盖性能问题。修复后需对三世界稳定帧率、点击/拖动、连续切换以及几何一致性重新回归。
